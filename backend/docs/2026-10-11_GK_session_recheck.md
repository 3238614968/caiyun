## 逐项差异与处理

| 项目 | HAR/参考事实 | 当前处理 |
| --- | --- | --- |
| 兑换请求 | POST、6 个 JSON 字段，prizeId 为数字，偏移为原图坐标 | 保持契约，使用用户选择的商品；此前已匹配 |
| H5 登录 | SDK 注册条目 1302 在登录条目 1352 之前；登录请求带设备 Cookie，响应两条 Set-Cookie 写 JWT 与用户域 | 原先登录客户端与兑换客户端分离；现将带签名的 H5 登录移到兑换 CookieJar 内，使用其最新 JWT |
| SSO | 页面 token 与该页面登录、SDK 页面上下文相配 | 不再把缓存 JWT 的有效期视为 SSO 有效期；新建页面会话前使用当前 Basic 凭据取新 SSO |
| HTTP 头 | 登录没有云盘原生 Basic/渠道头；签名使用当前时间及新 nonce/request ID | 新增独立 H5 会话登录函数，保留相同 HTTP transport/Jar，禁止登录重定向转发凭据 |
| JWT/用户域 | 登录 Set-Cookie 与后续请求属于同一账号 | 用登录响应更新该会话；用户域不一致则停止；预热任务复制独立认证上下文 |
| Cookie | 成功请求有 9 项 Cookie | 保留当前 SDK、JWT、用户域、cookieTokenKey、服务端 JSESSIONID；没有复制 HAR 旧值 |
| JSESSIONID 时序 | 1793 访问上报返回新值；1794 获取滑块仍带旧值；1798 兑换带新值 | HAR 并不能证明滑块只绑定 JSESSIONID。当前顺序完成访问上报，再取图、提交，继续使用同一 Jar |
| x-yun-tid | 成功样本的滑块响应及兑换请求均没有该头 | 删除把响应 trace 回传为挑战标识的假设；旧模拟测试也相应纠正 |
| 多任务并发 | getSlide 没有独立 challenge ID；此前只按账号+商品短暂去重 | 新增按真实账号串行的挑战/提交门控，跨商品和别名；这是防止挑战覆盖的修复，尚非 GK 原因的线上证实 |
| 预热失败 | 原代码即使 SDK/会话失败也会计入 readyAccounts | 必须完成设备和同会话登录后才标记就绪 |

账号门控在单进程使用互斥状态，在多实例使用有 owner 的 Redis 租约；不能取得分布式锁时停止。一次执行有 90 秒截止时间，租约 110 秒，防止租约先到期后旧请求继续提交。释放按 owner 校验，支持重复释放保护。不同账号可以并行。

## 尚未重建的 App 差异

- `cookieToken` 是 App 注入的 42 字符值，本 HAR 中与本次 H5 登录 SSO 不相同，也不是 cookieTokenKey 解码后的任一原生凭据段。没有证据支持直接把 SSO 填进去。
- SDK Go 编码虽符合 normal 5/2 协议，但目前只提交 HTTP 客户端拥有的上下文，没有真实浏览器的完整采集结果。设备接口 1100 不等于活动风控放行。
- 统计 Cookie 与真实 App WebView 原生上下文未完整重建。未捏造浏览器特征，未重放旧设备标识。

因此本轮修复的是确定的会话实现差异，**不是已证明消除了所有 GK**。
