# 2026-10-11 线上错误复核

## 写真主图校验：已复现并验证修复

对同一参考账号、同一个固定人像上传文件进行对照：

| 请求 | 实际返回 |
| --- | --- |
| 原 Go 通用云盘请求头 | HTTP 200，code=10000101，下游服务响应异常；无 masterId/taskId |
| 参考协议最小 Basic + Content-Type 请求头 | code=0000，请求成功；有 masterId/taskId |
| 修改后的实际 Go 妙云调用再次验证 | code=0000；有 masterId/taskId |

这次错误不是服务端判定图片“非正脸”。通用云盘请求附带了妙云接口不需要的 JWT、渠道信息等请求头。新增 `PostWithBasicAuth`：复用 HTTP transport 和读取超时，但不附带云盘默认头或 CookieJar，不携带凭据跟随重定向，不自动重放生成 POST。妙云目录记录、主图校验、创建形象、模型查询与合成均走该协议。

用户此前已授权固定参考人像。本轮验证仅到主图校验，在 createImage 前停止；每轮只回收本次上传文件，均返回清理成功。没有声称艺术照生成和活动完成位已经实测通过。

## 兑换与长期任务修复

- 修复月度保护误判：同系列已安排、正在执行、获取锁失败、仅提及同类商品的错误，不再作为“本月已兑换”依据。真实成功记录与明确月度限兑/重复兑奖回执仍保留保护。旧错误记录也使用新的识别逻辑，不需删除历史数据。
- 修复前端把“避免同月重复兑换”的调度提示标成“已兑换过”，改为本次跳过。
- 非 TokenManager 路径刷新失败时不再吞掉错误沿用旧 JWT。JWT 与 SSO 必须来自完整匹配的会话。
- 资格查询失败、缺少 exchangeCode、空值/布尔值/非整数值时停止提交，不再把未知资格视为允许兑换。
- 610/GK 在一次执行中停止自动重试，避免反复使用同一被拒绝会话。长期任务保留后续计划时间的执行机会；没有永久禁用账户或修改用户计划。

**GK 仍未验证解决。** 滑块坐标置信度高、exchangeCode=0 分别只证明本地匹配和资格允许；不能证明活动侧接受当前会话。当前会话仍与真实 App WebView 有差异，本轮没有提交真实奖品兑换，不能宣称抢兑成功。

2303 表示备份资格不足，2305 表示目标用户范围不满足，库存耗尽及真实月度重复兑换也保留真实结果。未通过修改结果绕过这些条件。

## 部署与验证

本轮后端版本：`2026.10.11-runtime-fixes-dirty`。同时更新并重启 API、Worker（以及其他运行同一二进制的实例）。仅更新 API 不会替换已经运行的旧 Worker。
