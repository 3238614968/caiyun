# 移动云盘任务覆盖与多账号核对

核对基线：mCloud 13.2.2 参考工作区的《全活动协议与参数手册》《隐藏活动与任务清单》《最终汇总报告》及青龙全任务脚本（2026-09-30）。任务槽位每天轮换，表内数量只作参考。此表区分**代码已实现**与**上游已验证完成**；本仓库的离线测试不会证明线上任务已计入奖励。

真实 HAR 二次对照已修复兑换和云朵领取的 V3 请求：`receive` 与任务中心按 `receiveList.recordId` 逐项 POST `receiveV3`，确认记录消失、余额和实际到账数量；抢兑使用 POST `exchangeV3`。详情见 [抓包对照报告](2026-09-30_protocol-云盘领取与抢兑-report.md)。隐藏奖励模块的待领盘点仍是只读摘要。

## 已接入

| 范围 | 当前实现 |
| --- | --- |
| 云朵中心 | 优先读取 `taskListV3` 的 `sign_in_3`、`newsign_139mail` 两表；旧版接口仅作回退。按任务状态领奖，真实行为后以 `doTaskPost(taskId)` 和 `key=task` 登记。 |
| 完成状态 | V3 的 `state` 优先于旧 `status`；点击、上传与领奖错误会汇入任务结果。趣玩 AI 和校园海报分别复查服务端完成位，不再把一次接口成功直接写成“任务已完成”。 |
| 上传、照片、AI、分享 | 已处理文件上传、PC 通道、照片上传、AI 相机/问答、知识库创建、分享文件及月上传计数；每次上传使用唯一内容，分享链接在上报后撤销，再清理临时文件。 |
| 独立活动 | TokenPK、MakeWish、趣玩 AI、校园海报均有独立任务模块；TokenPK 的 PC 上传任务使用 PC 通道并在真实行为后登记，MakeWish 补了拍照问 AI 和 `page/click` 登记。校园海报任务 33 已接入 `National_PosterMaking` 预签名上传、无鉴权 PUT 和完成回调。 |
| 趣玩 AI 图像任务 | `003`、`004`、`006`、`007`、`008`、`009`、`031`、`034`、`3Drenou` 已接入算法端点、样式参数、单人脸检查与广告位模板。算法受理与活动完成分别判断；以任务表的 `isComplete` 为准，避免将已计入活动的 `031` 因后续渲染失败误判。内置图片为虚构单人像。 |
| 趣玩 AI 新链路 | `204` 扫描文档采用 `algorithmLayout → resultList → scans/pic/save`，保存接口使用 `X-YUN-API-VERSION: 3` 和 AES-192-CBC 传输层；`011` AI 写真采用公开模板、云盘目录及上传、妙云正脸验证、建数字形象和艺术照生成；限时录音转写报送已接入。 |
| 隐藏活动领奖 | `hidden_rewards` 扫描 App 任务视图、邮箱短信通知奖励、月度福袋任务登记与抽奖、焕新权益有记录时激活、六个活动的未领奖品查询与领取；云朵中心 `receiveList` 只读盘点，不绕过滑块验证。消息推送任务支持类型 1/2/3 领奖并按服务端领取码区分结果。 |
| 许愿 AI 豆兑换 | `makewish_exchange` 查询可兑换状态后可消耗 300 AI 豆兑换；由于此操作不推进许愿任务完成位，默认关闭且不加入批次，需主动启用或单独执行。 |
| 139 邮箱互发 | `mail_mutual` 对同一用户下的活跃云盘账号按有向账号对互发。每对每自然月最多发一次，Redis `SETNX` 防止并发重复；每轮最多发送 `CAIYUN_MAIL_MUTUAL_MAX_SENDS_PER_RUN` 封，每日轮换起点以防失败账号对挡住后续收件人。 |
| 多账号批处理 | Worker、账号健康检查和每日统计使用账号 ID 游标遍历；前一批账号在刷新失败后被暂停，不会导致后续账号被 offset 分页跳过。 |
| 双账号活动互助 | `mutual_assist` 为每个目标账号选同一用户名下的下一个活跃账号，执行 MakeWish `1007`、TokenPK `7` 及趣玩 AI `taskSign=1` 的邀请助力；按服务端状态确认，`513` 资格限制记为待满足条件。 |
| 新增活动入口 | 通知同步、学生福利、领奖专区、会员日、美图备份、红包邀请、1T 新礼、抽奖码、家庭圈、AI Store、相册备份上报、邮箱版趣玩 AI、焕新权益均有协议层、任务层、执行器及前端名称。详细边界见 [二次核对记录](IMPLEMENTATION_RECHECK.md)。 |
| Token 生命周期 | Worker 通过 TokenManager 获取有效凭据；到期先刷新。仍有效的旧 JWT 可在预刷新失败时短暂继续使用。无可用凭据且连续刷新失败达到阈值后才暂停账号。更新授权或手动启用会重置失败计数并清除缓存；任务运行器同步最新原始 Token，抢兑路径在刷新失败时不再回退旧 JWT。 |

## 尚不能认定全部完成

| 范围 | 原因或所需条件 |
| --- | --- |
| 139 邮箱任务 `1004` | 邮件 `mbox:compose` 成功只证明邮件发出；参考环境的 `disk:mailReportToMQ` 返回 HTTP 500，云盘任务可能仍为 `WAIT`。任务日志分别记录发信和上报/复查结果。 |
| 139 邮箱 `1014`、`1020` | 参考环境的 PDF 转换/邮件转存接口不可用或返回 998，不能用点击代替真实邮箱行为。 |
| TokenPK `7`、MakeWish `1007` | 已接入双账号助力，但仍受助力方当月资格限制。只有一个活跃账号、助力方不符合资格或服务端尚未更新状态时不能声称完成。 |
| 趣玩 AI 图像/扫描/写真任务 | 代码链路与素材已具备，但尚未用授权账号实测上游算法是否接受合成人像、当前模板及账号资格；不能把离线模拟测试等同于活动完成。AI 写真会在账号云盘创建「AI工具箱本地上传/AI写真/我的形象」目录。 |
| 校园海报 `33` | 预签名上传与回调已有离线协议测试；来源文档对“上传后是否还需步骤点击”存在版本差异，代码会先复查任务状态，仅在未完成时登记步骤。线上完成位仍需授权账号验证。 |
| 139 邮箱 `1057` | 已按来源脚本的 `sourceChannel=10175` 调用工作台对话和写作接口，是否翻转任务完成位需线上确认。 |
| 通知、公众号、App 内 WebView、小程序与跨月任务 | 依赖设备状态、真人操作、活动资格或时间门槛，不能仅靠任务点击证明完成。 |

## 离线验证

- `cd backend && go test ./... && go vet ./...`
- `cd frontend && vue-tsc --noEmit -p tsconfig.json && eslint src --ext .ts,.vue && vitest run`
- 邮箱协议测试用模拟 HTTP 响应验证邮箱专用 SSO、XML 登录/发信和上报失败分离；未使用参考目录中的真实凭据或实际发送邮件。
- 趣玩 AI 图像任务的内置素材位于 `backend/internal/core/api/assets/ai-task-portrait.png`，由内置 imagegen 工具生成，提示词为“单个虚构成人、正面半身、清晰无障碍的人脸、自然光和纯色背景，无文字或标志”。
- Windows 本地 Go 配置为 `CGO_ENABLED=0` 且无 C 编译器，`go test -race` 无法在此环境执行。
